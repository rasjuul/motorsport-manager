# My instructions for motorsport-manager

- Never overwrite existing configuration files.
- Ask for my approval before changing existing notes. Create new dated notes for progress and hand-offs.
- Keep files, code identifiers, comments, documentation, commit messages and uploads in English. Write project documentation in my first-person voice without inventing experience, authorship claims or test results.

- Never publish passwords, tokens, credentials, personal information or unrelated private material. If any are detected, stop uploading affected files, report the issue without revealing values, and prepare a sanitized version. Never copy unrelated secret-upload approvals into this public repository.
- Use Git Credential Manager for local authentication. Keep credentials and local approval records outside tracked files.
- Confirm my approval covers the concrete files being uploaded. Approval for an earlier upload does not authorize a new payload.
- Preserve source files and source references. Do not import my unrelated coursework or unrelated notes.
- Keep a project card with purpose, status, sources, next steps and the code repository.
- Distinguish planned, implemented, documented, tested and live-verified work. Do not claim the game runs until it has been run successfully.
- After every completed creation or change, create a dated progress note and upload it within my approved scope. Record changes, reasons, relevant files, verification results and next steps.
- When I pause or stop for the day, create a dated hand-off and back up source code, relevant save files and status to a separate project folder in my private backup location. Do not overwrite existing backups, configurations or notes. A local backup and a GitHub upload are separate actions; verify and report both independently. Follow the backup destination rules when writing or uploading there.
- On resuming work, read the latest project hand-off before reconstructing status from chat history. If there is none, say so.
- Follow [documentation and hand-off rules](rules/Documentation-and-handoff.md) and [scripts and file structure rules](rules/Scripts-and-file-structure.md).
- Keep the project appropriate to my learning level. Explain new concepts, help me write and understand the central game logic, and challenge scope growth before adding features.
